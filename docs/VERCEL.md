# Развёртывание SUPER CUBE на Vercel

Проект публикуется как Vercel Container Function через файл Dockerfile.vercel. Он запускает тот же Express-сервер, что и основной Docker образ. HTML-страницы находятся в корне репозитория; CSS, JavaScript и остальные публичные ресурсы раздаются из каталога public. Страницы профиля и администратора по-прежнему выдаются только после проверки сессии.

## Внешние сервисы

Vercel не запускает docker-compose.yml. Перед публикацией настройте внешние сервисы и доступные из Vercel адреса:

- PostgreSQL 16 или совместимый управляемый PostgreSQL.
- Data API из каталога data-service, подключённый к PostgreSQL. В Data API задайте DATABASE_URL, DATA_API_TOKEN и DATABASE_SSL=1, если провайдер требует TLS.
- Отдельный game-runtime manager, если используете игры с серверной частью. Он должен иметь доступ к Docker Engine и к тем же архивам игр, а SERVER_GAME_RUNTIME_URL должен быть доступен платформе из интернета. Не публикуйте неаутентифицированный Docker API.
- SMTP для входа по email.

В Vercel Project Settings → Environment Variables задайте как минимум:

- NODE_ENV=production
- BASE_URL=https://ваш-домен (если BASE_URL не задан, используется VERCEL_URL)
- SESSION_SECRET — случайное значение длиной минимум 32 символа
- OTP_PEPPER — уникальный случайный секрет
- ADMIN_LOGIN, ADMIN_PASSWORD и ADMIN_EMAIL
- DATA_API_URL и DATA_API_TOKEN
- SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM
- SERVER_GAME_RUNTIME_URL и SERVER_GAME_RUNTIME_TOKEN, если включён серверный runtime

Секреты задавайте для Production, Preview и Development только там, где они нужны. Не добавляйте секреты в репозиторий или клиентский код. Для Preview используйте отдельную базу и отдельные токены.

## Хранилище и ограничения

Локальная файловая система Vercel временная. Текущая загрузка игровых ZIP, аватаров и капсул сохраняет файлы в STORAGE_DIR, а runtime игр читает ZIP из общего файлового хранилища. Поэтому файловые загрузки и серверные игры нельзя считать готовыми для production на Vercel до миграции на постоянное общее хранилище (например, S3-совместимое хранилище или Vercel Blob) и обновления platform API и runtime manager для чтения, записи и удаления через этот адаптер.

У Vercel Functions есть лимит размера тела запроса/ответа 4.5 MB. Загрузка ZIP (до 100 MB) и капсул (до 12 MB) сейчас превышает этот лимит. Перед включением загрузок перенесите их на прямую загрузку в объектное хранилище с короткоживущими подписанными URL. Загрузка аватаров ограничена 2 MB, но также должна быть переведена на постоянное хранилище.

Vercel контейнеры не являются заменой PostgreSQL, Data API или Docker runtime: эти процессы должны быть развёрнуты отдельно. Веб-сайт и API могут запускаться отдельно, если переменные окружения и внешние адреса настроены.

## Публикация

1. Импортируйте Git-репозиторий в Vercel и оставьте корень проекта корнем проекта.
2. Убедитесь, что сборка использует Dockerfile.vercel. Не задавайте команду сборки, которая запускает Docker Compose.
3. Добавьте переменные окружения для Production и Preview.
4. Подключите домен и установите BASE_URL в его HTTPS-адрес.
5. После деплоя проверьте /health, регистрацию по email, сессию после запроса и загрузку статических страниц.
6. Включайте загрузку игр и серверные игры только после настройки постоянного хранилища и runtime manager.
