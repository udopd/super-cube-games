# SUPER CUBE — server-game proxy body fix

## Observations
- User Docker logs confirm the `durak-online` container starts and listens on `0.0.0.0:3000`.
- Runtime manager and PostgreSQL/Data API containers were healthy.
- The runtime manager application handler currently emits 200/401/404/503; an HTTP 400 without an app log may be generated by Node's HTTP parser before `handler()` receives the request, or may come from a stale/different request path/image.
- A confirmed proxy bug: Express `express.json()` consumes request bodies before `serveServerGame()` runs, but `proxyServerGame()` originally called `req.pipe(upstream)`. For a parsed JSON POST, that can send no bytes while preserving the original `Content-Length`, causing an incomplete request and socket hang up.

## Changes
- Platform server stores parsed request bytes via Express body-parser `verify` into `req.rawBody`.
- `proxyServerGame()` replays those bytes with a corrected Content-Length. Unparsed streams continue to use `req.pipe()`.
- Runtime manager logs each method/path/status/duration.
- Added a `clientError` listener to log HTTP parser failures that would otherwise result in an opaque HTTP 400.
- Runtime manager request failures now identify the method and path.
- Added a unit regression test `scripts/test-server-game-proxy-body.mjs`.

## Apply
1. Keep the existing `.env` and Docker volumes.
2. Copy the updated project files over the existing project. Minimum changed files: `server.js`, `src/server-game-runtime.js`, `runtime-service/server.js`, `package.json`, `scripts/test-server-game-proxy-body.mjs`; README/HANDOFF are documentation updates.
3. Rebuild/recreate both affected services: `docker compose build --no-cache platform game-runtime` then `docker compose up -d --force-recreate platform game-runtime`.
4. Inspect logs: `docker compose logs --since=5m --timestamps platform game-runtime`. Expected logs should show runtime start and proxied API routes with HTTP status.

## Verification
- `npm test` passed on this tree.
- Static checks do not replace runtime integration tests against the user's Docker Desktop/PostgreSQL instance.
